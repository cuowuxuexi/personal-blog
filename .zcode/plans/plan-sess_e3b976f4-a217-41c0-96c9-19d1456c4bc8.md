## 实施目标

把已验收的公众号排版固化为发布面板的第二种预览。周记 Markdown 继续是唯一内容源；公众号 HTML 是发布任务快照内的本地临时产物，不进入 Git 发布清单。

最终流程：

1. 在发布面板编辑周记。
2. 点击“保存并生成发布预览”。
3. 同一发布任务同时生成：
   - 博客发布前预览；
   - 公众号排版预览。
4. 公众号预览立即可看，图片使用快照中的本地资源。
5. 当生产 SHA 校验成功，或单独检查确认所有图片已在线后，“复制公众号全文”解锁。
6. 复制时把预览用的本地图片地址替换为 `https://blog.cuowo.win/...`，再复制富文本到剪贴板。

## 1. 新增公众号渲染模块

新增 `panel/lib/wechat.mjs`，职责保持纯粹，不处理 Git、发布或 HTTP。

主要能力：

- 使用 `parseFrontmatter()`、`parseEntries()`、`parseChrome()` 读取现有周记格式。
- 在解析条目前复用：
  - `normalizeDisplayMath()`；
  - `normalizeWeeklyEntryHeadings()`。
- 新增直接依赖 `markdown-it`，使用 `html: true`、`breaks: true` 渲染条目正文，避免依赖 VitePress 标记为 experimental 的 Node API。
- 将 Markdown 输出转换为全内联样式的公众号安全 HTML。
- 同时返回：
  - 完整预览页 HTML；
  - 正文 HTML；
  - 所有引用图片的生产 URL；
  - 建议标题与摘要。

固定采用已经验收的排版规则：

- 正文 `16px / 28px`，宋体衬线字体栈；
- AI 与生活强调色 `#0d7a5f`；
- 投资强调色 `#2949a4`；
- 条目标题与网址使用 `#e66700`；
- 条目标题为纯文本；`link-href` 完整网址单独显示在标题下；
- 副标题为纯文本；`subtitle-href` 完整网址单独显示在副标题下；
- 标签、头图、正文、日期、分隔线顺序固定；
- 展开/收起和隐藏大纲不导出；
- 日期缺省时回退到文章 frontmatter 日期；
- 封面、栏目图标、badge、条目头图和正文图片都支持；
- 表格、列表、引用、标题、行内代码、代码块和软换行有对应内联样式；
- 块公式降级为可读的公式文本块，不依赖公众号运行 MathJax；
- 旧的无封面、无 issue、使用 `tag` 的周记也可以生成。

## 2. 公众号预览使用本地图片，复制使用线上图片

预览页中的每个博客图片包含两套地址：

- `src`：发布快照中的本地图片路由，确保新图尚未部署时预览也完整；
- `data-online-src`：对应的生产地址，例如 `https://blog.cuowo.win/images/weekly/xxx.webp`。

复制按钮执行时：

1. 克隆 `#article`；
2. 把克隆体内所有 `img[data-online-src]` 的 `src` 换成生产地址；
3. 优先通过 Clipboard API 写入 `text/html` 和 `text/plain`；
4. 不可用时回退到 DOM Selection + `document.execCommand('copy')`；
5. 工具栏、状态提示和按钮不进入剪贴板。

## 3. 接入发布快照

修改 `panel/lib/publish-job.mjs`。

在 `preparePublication()` 中：

- 完成 `overlaySnapshot()` 后，从 `draft.files` 中定位唯一的周记 Markdown；
- 从隔离快照读取该文件，而不是从工作区读取；
- 生成任务专属的公众号 HTML；
- 将产物写入快照下的私有目录；
- 保存公众号预览文件路径、图片 URL、检查状态和检查时间；
- 公众号生成失败会令准备阶段明确失败，避免博客预览与公众号预览来源不一致；
- 图片线上检查失败只锁定复制，不阻断博客发布准备。

扩展 `publicJob()`，返回：

```js
wechatPreview: {
  url,
  status,
  copyAllowed,
  checkedAt,
  missingAssets
}
```

其中 `copyAllowed` 由服务端计算：

- 所有图片已在线；或
- 发布任务已经通过生产 SHA 校验进入 `Published`。

公众号图片状态作为并行子状态，不增加或改变现有博客发布状态机。

在 `verifyProduction()` 成功分支中，将公众号状态标记为生产已验证并自动解锁复制。

## 4. 图片在线检查

修改 `panel/lib/probes.mjs`，增加 `onlineAssets({ urls })`：

- 检查渲染结果引用的生产图片地址；
- 记录缺失或网络失败的地址；
- 返回全在线或等待上线状态；
- 不修改博客发布状态。

修改 `panel/lib/publish-job.mjs`，增加重新检查函数。

修改 `panel/server.mjs`，增加：

```text
POST /api/publish/jobs/:jobId/check-wechat-assets
```

适用于：

- 历史图片本来就在线，可在发布前解锁复制；
- 部署完成后手动重试；
- 生产 SHA 校验超时但图片其实已经上线。

## 5. 安全提供公众号预览和快照图片

修改 `panel/server.mjs`：

- 增加 `GET /wechat-preview/:jobId/`，只提供该任务生成的公众号 HTML；
- 增加该任务快照图片的受限路由；
- 使用现有 `isPathInside()` 路径保护；
- 不允许通过路径穿越读取快照或仓库中的其他文件；
- 未生成、未知任务或不存在资源返回 404。

生成物不加入 manifest，不修改 `panel/lib/scope.mjs`，也不会提交到公开博客。

## 6. 发布面板界面

修改：

- `panel/public/index.html`
- `panel/public/app.js`
- `panel/public/style.css`

在现有发布任务区域增加：

- “公众号预览”链接；
- 公众号状态文字；
- “重新检查线上图片”按钮。

`renderJob()` 根据状态展示：

- 尚未生成；
- 图片检查中；
- 有 N 张图片尚未上线，预览可看但复制锁定；
- 图片全部在线，可以复制；
- 博客生产 SHA 已验证，可以复制。

复制操作只存在于公众号预览页，面板本身不重复实现富文本复制。

公众号预览页会读取当前任务 API；页面已经打开时，在发布完成后可自动刷新状态并解锁按钮。

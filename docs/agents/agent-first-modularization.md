# Agent-first 模块化实施计划

状态：目标架构已由作者确认；Phase 0–2 已终验通过（Phase 2 acceptance：`phase2-build-time-projections-acceptance-report.md`）。2026-08-24 架构加深（提案 01–06，改刚好/中档）已独立验收并进入 `origin/main`：阶段 3 与阶段 5 按该范围完成。阶段 4 与阶段 6 其余项未做。证据：`.planning/架构加深/验收报告.md`。

## 目标

让 Cursor、Pi 和其他 Agent 从自然语言任务稳定路由到一个能力、少量源码和正确验证，降低宽泛搜索、重复上下文、跨模块误改和人工同步错误。

完成门槛：8 个真实任务中至少 7 个能够从 `PROJECT.md` 或对应 Skill 一跳命中正确能力；确定方案前主要实现文件不超过 3 个；首次选择的验证命令正确；不发生跨能力误改。

## 不变量

- 默认保持公开 URL、正文观点、整体视觉、发布门禁和双站部署行为。
- 结构迁移不覆盖当前工作区已有且无关的修改。
- 不自动 commit、push、发布或部署。
- 活跃内容违反合同必须失败；历史只读内容在迁移期可先告警。
- 现有 Markdown 采用路径适配优先，只在稳定字段成为合同时增量补 frontmatter。

## 目标能力

1. 内容创作
2. 内容目录 / 信息架构
3. 站点呈现
4. 发布面板
5. 发布部署
6. Agent 导航

依赖方向与 live 入口见根 `PROJECT.md`。内容权威决定见 ADR 0002；持仓公开政策见 ADR 0003。

## 8 个路由基准

1. 新增一期周记。
2. 修改一个既有 `WeeklyEntry`。
3. 调整周记页面视觉。
4. 新增一个投研标的或研究地图。
5. 修改首页文案或区块。
6. 修改发布面板的一个字段或按钮行为。
7. 修改生产校验或部署重试逻辑。
8. 修改顶栏、侧栏或内容目录关系。

每项记录：首次入口、读取的主要文件、是否宽泛搜索、错误候选、返工次数、验证命令和结果。token 只作辅助指标。

## 依赖策略

允许少量用途明确的依赖，例如稳定的 frontmatter/YAML 解析器和浏览器 smoke 工具。新依赖必须替代真实的手写复杂度；不为目录重构引入前端框架、DI 容器或代码生成平台。

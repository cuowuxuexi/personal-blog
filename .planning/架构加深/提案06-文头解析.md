# 提案 06：文章开头只认一套拆法

状态：已按「改刚好」批准（2026-08-24）。批准不等于改代码。

## 一句话

标题、日期、修订日这些写在文章最上面的字段，只按内容目录那一套来拆。面板和旧日记不再各拷一份。你写文章的方式不变。

## 小 / 中 / 大 是什么意思

**少改：** 只有面板去调用目录那一套。旧日记还自己拆。以后加字段，日记那边仍可能看不见。

**改刚好（本文按这个写）：**  
面板写入文章、投研投影、Hermes 旧页，都走目录那一套拆法。引号、数字、正文从哪开始，只在一处改。  
面板开机时若已经带齐栏目说明，浏览器里那份「缺了就自己编」的兜底表删掉，只认开机带来的那份。开机若还允许缺字段，兜底只留一处，不在服务端和网页各写一张。

**改太多：** 换成完整 YAML 库、改日期字段合同、让投研文头长出一套新字段。这次不做。日期怎么用，`CONTEXT.md` 里已经定了。

## 你已经定下的

- 先写提案，不改代码。  
- 前五条不回头：发布三段、保存即写入、范围只认目录、面板三件工作、投研结构投影。  
- 本条只收拢「怎么把文头拆开」，不改你怎么写正文。

## 现在哪里别扭

内容目录里已经有一份拆法，而且写着：调用方不要再写一套。

面板保存周记/历程时，自己又拆一遍。双引号的处理还不一样（一份当 JSON，一份只剥引号）。Hermes 旧日记再拆一遍，而且不把正文拆出来，数字也不转成数字。

今天你看不出来。哪天加一个字段（比如修订日），或标题里带引号，就可能：这边认、那边当没看见，首页最近更新和面板对不上。

栏目说明也有类似的两张表：服务端拼好能力，网页缺字段时再按周记/历程自己补一套。开机若其实一直是完整的，网页那张表就是多余的浅拷贝。

删除测试：把「目录这份拆法」删掉，三处又会各写各的。所以这份要留。把后两份拷贝删掉，麻烦消失——它们不值得加深。

## 改完你怎么用（应该和今天一样）

1. 文章最上面还是那几行：`title`、`date`、可选 `revisionDate`。  
2. 普通改字不改 `date`。重要修订才由你（或明确说要改的人）写 `revisionDate`。  
3. 面板保存、站点目录、旧日记列表，看到的是同一套字段。  
4. Hermes 仍是停用的栏目，不为它新开一天，除非你明文重开。只是万一读旧页，拆法和别处一致。

不改你怎么写条目正文。不改发布要点几次。

## 门里面怎么改（仍是人话）

**拆文头只留目录那一处**  
面板写入文章、校验、公众号认正文、Hermes 读旧页，都叫这一处。后两份函数删掉。

**先对一下再删**  
删之前用现有文章跑一遍：三份拆法对同一篇，字段应对齐。对不齐的，以目录那份为准，并补测试钉住。双引号按目录那份剥引号，不再在面板里走一套 JSON。

**栏目说明一张表**  
开机数据齐，就删网页兜底。开机还允许缺，兜底只住在种类适配器那一处，网页不要第二张周记/历程表。

## 不改什么

- 日期字段合同：`date` 稳定；`revisionDate` 只标重要修订；不引入平行的 `updated`。  
- 不从 Git、文件修改时间自动填修订日。  
- 投研默认不进最近更新。  
- 不换 YAML 库，不加新文头字段。  
- 不重开 Hermes。  
- 不改提案 01–05 已经定的用法。

## 改完怎么算验收

1. 同一篇周记、一篇历程、一篇旧 Hermes：只有一套拆法被调用；面板和目录看到的 `title` / `date` / `revisionDate` 一致。  
2. 带双引号的标题，两边不会一个留下引号、一个剥掉。  
3. 加测试：目录这份拆法是唯一入口；面板、Hermes 不再各自 export 一份同名拆法。  
4. 开机缺字段的兜底：要么没有，要么只有一处。  
5. `pnpm test:content`、`pnpm test:panel` 要过。本条不改你点的按钮。

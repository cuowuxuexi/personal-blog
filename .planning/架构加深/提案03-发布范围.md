# 提案 03：能发哪些文件，只认一份名单

状态：已按「改刚好」批准（2026-08-24）。批准不等于改代码。

## 一句话

面板能发的还是周记和历程，投研继续发不了。只把「文章在哪、图在哪」收成一份，发的时候和查图的时候都去问这一份，不再抄三遍。

## 小 / 中 / 大 是什么意思

**少改：** 只有「发不发得过」去问目录。查缺图的那份还自己记路径。漏改的口还在。

**改刚好（本文按这个写）：**  
「周记在哪、历程在哪、图在哪」只认内容目录里那一份。发的时候只问三句人话：在范围内吗？被拦住了吗？历程是不是恰好一篇正文？查图也问同一份，不再自己写死 `/images/weekly/`、`/images/journey/`。

**改太多：** 顺手让面板也能改投研，或重做整张「谁许面板写」。那是换发布门禁，不是修抄名单。这次不做。

## 你已经定下的

- 先写提案，不改代码。  
- 你能发的东西不变：周记、历程，加上它们真正用到的图。  
- 按「改刚好」来。  
- 投研、哲学、大问题、Hermes 继续写死拦住。  
- Cursor / Pi 改投研又慢又容易错，不塞进这一条。放到第 5 条（目录少抄一遍）；若还不够，再单独谈「要不要给投研做面板」。

## 现在哪里别扭

内容目录里已经写过：生活周记在 `docs/AI与生活`，投资周记在 `docs/投资/周记`，历程在 `docs/AI与生活/我的AI历程`，图分别在 weekly / journey 目录。

发的时候，范围检查又写一遍允许和禁止的前缀。查缺图时再写一遍根目录和图片网址。组清单、认「哪篇是正文」时，发布任务里还有一份路径判断。

你日常发周记能过。别扭在：以后挪目录、加一种可发内容，漏改一处，就可能把不该发的打进清单，或把该发的图判成缺图。

删除测试：把「这份文件能不能进这次发布」整块删掉，门禁会散到准备、确认、查图各处。所以范围检查要留，而且值得加深——加深成「问目录里的事实，自己只做政策」，不是再造一套路径表。

## 改完你怎么用（应该和今天一样）

1. 周记任务：清单里是当期正文，加上正文真正引用的周记图。  
2. 历程任务：恰好一篇历程正文，加上这篇真正引用的历程图。不能拿历程任务去发周记，也不能一次塞两篇篇章。  
3. 工作树里若还有投研、哲学、大问题、Hermes、面板代码、站点配置，它们出现在「未纳入」，不能被确认发布带上去。  
4. 缺图仍然会在准备阶段被拦住。  
5. 你还是先准备、再确认。确认只点一次。

不自动发布。不从面板创建、改名、删除历程具名篇章。

## 门里面怎么改（仍是人话）

**事实只住在内容目录**  
每种内容自己带着：正文目录、图片目录、图片网址前缀。面板不再手抄这三样。

**范围检查只做政策**  
拿着目录里的事实，回答：这个文件在这次任务的范围内吗？是不是被写死拦住的（投研 / 哲学 / 大问题 / Hermes / 站点配置 / 面板自己）？历程是不是恰好一篇正文？

**查图、组清单问同一份**  
缺哪些图、哪些路径算正文，都跟范围检查问同一套目录事实。发布任务里那份再手写的「从哪开头算正文」，删掉。

**拦住名单仍然写死**  
投研许不许面板写，不改成「看目录上的勾」。目录里投研本来就没有面板入口，但哲学、大问题等不一定都登记成种类。写死拦住更保险，也不会把「Agent 改投研好不好用」和「发周记别抄路径」搅在一起。

- 不创建、不改名、不删除历程具名篇章。  
- 不拆发布任务三段（提案 01）。  
- 不改保存是不是立刻写文章（提案 02）。

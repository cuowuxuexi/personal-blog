# 研究笔记: 投研标的上线缺口

对照时间：2026-08-27。权威是 live 源码，不是本轮对话记忆。

## 来源

### 作者工作流（本轮对话）
- 投资系统里完成研究和战役：画布 → HTML → 落成草稿。
- 作者自己切换到本仓，把草稿交给 Cursor 或其他 Agent，口令是「写入博客」。
- 本仓 Agent 的起点是交稿，不是重做研究。
- 读者面只要恒瑞这种完整档案页。后续新研究结果在该公司下新开一章，也是完整页。
- 画布 HTML 不作为投研读者主阅读面。周记里的独立 HTML（如拼多多表）是另一条，不动。
- 后面会不断加新标的。不自动从投资系统同步。

### 现行协议
- `.agents/skills/blog-editor/references/content-domains.md`：新标的只写目录 `index.md` 文头 + README；清单和 `/投资/投研/` sidebar 应由投影生成，不要手改 `config.mts`。
- `docs/agents/research-publishing.md`：Gate 1 起草前讨论；Gate 2 预览后才允许 push/deploy。回源走 gitignored 的 `research-sources.local.yaml`。
- `ops/腾讯云备案与博客接入-Cursor操作说明.md`：周记走面板；投研/主题手工构建再上传。`push main` 只更新 Pages。未获作者要求不得手动 upload。
- `.planning/架构加深/提案05-投研投影.md`：结构声明一次；面板不碰投研；不自动同步指挥部。

## 综合发现

### 已经自动的
- 行业页 `<IndustryDirectory>`、投研总览 `<ResearchDirectory>`、投资总览 `<TrackedSubjectList>` 从 `docs/投资/投研/**/*.md` 的文头投影。
- 主题已注册这些组件（`docs/.vitepress/theme/index.ts`，本轮恒瑞上线时补上）。本地行业清单能渲染。
- `managed-sidebar-fs.mjs` 已能算出 `researchIndustrySidebarGroups`。

### 还要手改的
- `docs/.vitepress/config.mts` 的 `/投资/投研/` 侧栏仍整树手写。注释写着「静态投研壳仍手写」。恒瑞是手插的一行。
- `content-catalog/verify/overview.mjs` 把医药标的数写死为 2。再加一家会红。
- `docs/.vitepress/site-projection.test.mjs` 把医药标的链接写死。再加一家会红。
- 医药知识图谱「公司映射」、卖药路径卡，仍手写。这是内容判断，应保留。
- `inferResearchRole` 只认 `行业/标的/index.md`。`行业/标的/章节/index.md` 现在不是结构节点：VitePress 能打开整页，但行业清单和投影侧栏都看不见。步 1 要补 `subject-chapter`，侧栏挂在该公司下面；行业清单仍只计公司。

### 上传口
- `package.json` 没有 `publish:guonei`。
- 面板确认发布会 push + 构建 + `uploadDist`；投研不在面板编辑范围（提案 03 / `panel/scope.test.mjs`）。
- `panel/lib/guonei.mjs` 的 `uploadDist` 已支持增量；国内站 `build.json` 和预期基线不一致时退回全量。恒瑞那次国内站还停在 `f339514`，只能全量。
- 手工上传必须写 `build.json`，否则面板会以为国内站还在旧提交。

### 接线测试的坑
- live `config.mts` 已 import `managed-sidebar-fs`（周记/历程 spread），因此 wiring 模式是 `spread`。
- `site-projection.test.mjs` 在 spread 模式下要求投研、哲学、大问题三处都接 spread。只接投研侧栏、不改另外两处，测试会红。
- 实现步 1 时：要么三处一起接上投影，要么先把测试改成「各 section 只要求自己的 spread」。不要只改投研却假装测试已经绿。

### Agent 耗时（恒瑞上线复盘）
- 机器时间短：`docs:build` 约 8s，上传约 23s。
- 长的是：把「挂目录」当成重新研究、对账写死个数、侧栏手写、主题组件未注册、没有固定上传口、工作区里夹着周记/面板未提交改动。

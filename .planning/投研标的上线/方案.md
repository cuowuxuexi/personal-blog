## 一句话

研究和战役在投资系统里做完。你把草稿带到本仓，对 Agent 说「写入博客」。目录自动认，上传走固定口。你说「上传」才上 cuowo.cn。

## 你已经定下的

- 投资系统完成研究、战役、画布到 HTML 的草稿。作者自己交到本仓，不自动同步。
- 本仓 Agent 的默认口令是「写入博客」：按稿改写成档案页，不重做研究。
- 投研标的读者面只要完整档案页（恒瑞那种：顶栏、侧栏、面包屑、页脚）。不走独立 HTML，不嵌 `<StandaloneHtml>`。
- 一家公司一个档案根。后续新研究结果在该公司下新开一章，仍是完整页。
- 新行业 ≠ 旧行业下加一家公司。
- 知识图谱上的业务位置仍手写。
- 面板不改成投研编辑器；最多加「上传当前站点」。
- 人闸保留：作者说「上传」才传。

## 现在哪里别扭

认识、战役、草稿都在投资系统里做完了。你交到本仓后，写入和上线还要再办一圈手续：

1. 行业清单其实已经会扫目录。侧栏却还在 `config.mts` 里手写。加一家公司要再插一行。
2. 对账把「医药必须几家」写死。下一家一加，测试先红。
3. 投研不在面板里。上传靠人翻运维说明，容易和周记、面板未提交改动搅在一起。
4. Agent 听到「写入博客」还会按 Gate 1 回头研究一遍。慢的不是构建，是把交稿当成重新研究。

提案 05 已经把总览清单交给投影。主题组件也注册了。缺的是侧栏接线、活的对账、固定上传口、两句触发分流。

## 改完你怎么用

**现有行业下写入一家公司：**

1. 投资系统里研究和战役做完，草稿在你手里。
2. 你换到本仓，把稿交给 Agent，说「写入博客」。
3. Agent 把稿改写成档案 Markdown。这家还没有页，就建档案根；已经有了，就在该公司下新开一章。两页都是恒瑞那种完整页。
4. 知识图谱要不要加一句，你自己写。机器不替你判断卖药还是 CXO。
5. 预览行业页（仍只见公司）、侧栏（公司下能看到章节）、刚写入的那一页。不用改站点配置。
6. 你说「上传」。机器只提交这次写入的文件，push `main`，再传到 cuowo.cn。

**你说「写入博客」：**  
按你交来的稿落页。不回投资系统。

**你说「上传」：**  
只发布。不改认识。

**你说「按投资系统改认识」：**  
才回源私有研究，改正文。这是例外，不是交稿默认口。

**新开一个行业：**  
另走一轮：行业首页、研究地图空壳、侧栏一级入口。不是「再加一家公司」。

## 分三步做

批准后按这个顺序改代码。一步做完再开下一步。

### 步 1：目录自动认

目标：现有行业下多一份标的档案，只新增目录和正文；该公司下再开章节，侧栏能挂上。

- 把 `researchIndustrySidebarGroups` 接到 `/投资/投研/`。哲学、大问题侧栏要么一并接上，要么先改测试，别只接投研却假装已经绿。
- 投影补认 `行业/标的/章节/index.md`（章节）。行业清单、跟踪标的仍只显示公司。侧栏在公司下展开章节。
- 对账改成「行业页清单、侧栏、磁盘分类一致」，不要写死「医药必须 N 家」。
- 行业页、投研总览、投资总览继续用现有投影组件。
- 知识图谱、路径卡、开篇判断仍手写。

验收：再加一家，不改 `config.mts`，侧栏和清单都有公司；再在该公司下加一章，侧栏能点进完整页；`pnpm test:content` 绿。

### 步 2：固定上传口

目标：投研上线不再翻运维说明现拼。

- 加一条命令，例如 `pnpm publish:guonei`：构建、写 `build.json`、调现成的 `uploadDist`。
- 也可以在面板加「上传当前站点」。只传已经构建好的站点，不开放投研编辑。
- 上传包只含这次要上的投研改动。周记图、面板半成品、`package.json` 杂项不夹带。
- `push main` 和国内上传一起做，避免 cuowo.cn 的 SHA 掉队，下次才能走增量。
- 磁盘低于 800MB、UHT 8080、备案号、公网安备，沿用现有红线。

验收：作者说「上传」之后，有一条固定命令能走完；`cuowo.cn/build.json` 的 SHA 等于刚推上去的提交。

### 步 3：Agent 两句话

目标：同样一句话，不要再走研究全流程。

- 路由写进 blog-editor / 投研发布协议：  
  「写入博客」→ 按交来的稿落页 + 预览 + 等人闸。  
  「上传」→ 固定口发布。  
  「按投资系统改认识」→ 回源再改正文。
- 新行业、新地图、正式结论，仍先问再写。
- 私有路径、凭证、`research-sources.local.yaml` 不上公开 git。

验收：下一次「写入博客」不再重跑 Gate 1 讨论稿。

## 建档形态

投研标的的读者面只有一种：完整档案页。画布 HTML 停在投资系统，写入时改写成 Markdown。

| 形态 | 路径 | 读者看到 | 清单怎么认 |
| --- | --- | --- | --- |
| 档案根 | `docs/投资/投研/<行业>/<公司>/index.md` | 恒瑞这种完整页 | 行业清单、侧栏出现公司 |
| 章节页 | `docs/投资/投研/<行业>/<公司>/<标题>/index.md` | 同一套完整页，面包屑多一节 | 行业清单不另计一家；侧栏挂在该公司下 |
| 地图入口 | 研究地图上的一句 | 仍是地图页 | 不自动生成 |
| 新行业 | 行业首页 + 地图空壳 | 投研总览多一行 | 另走一轮，不是「再加一家」 |

周记里的独立 HTML（如拼多多表）不在这条路上，不动。

缺档案可以只在地图上挂名字，并写明「档案未建」。有档案也不强制写进图谱。

## 权威与门禁

| 事情 | 谁说了算 |
| --- | --- |
| 事实、正式结论、持仓相关认识 | 投资系统 |
| 读者看见的句子、排序、状态标签 | 本仓 Markdown |
| 行业 / 地图 / 标的出现在哪 | 目录 + 文头，构建投影 |
| 图谱上的业务位置 | 你手写 |
| 上 cuowo.cn | 你说「上传」 |
| 上 blog.cuowo.win | 随 `push main` |

没有自动同步，没有自动发布。

## 不改什么

- 不把投资系统做成博客后台。
- 不把面板做成投研编辑器。
- 不取消「上传」这道人闸。
- 不把投研标的做成独立 HTML 或 iframe 嵌页。
- 不自动写知识图谱角色。
- 未获「上传」不 push、不传 cuowo.cn。

## 验收整条链

现有行业下加一家公开学习档案，以及在已有公司下再开一章时：

1. 只新增该档案根或章节目录和必要正文，都是完整档案页。
2. 不改站点配置。行业清单只见公司；侧栏在公司下能进章节。
3. 作者说「上传」后，走固定口；国内站和 `main` 的 SHA 一致。
4. Agent 不再把「写入博客」当成重新研究，也不把画布稿落成独立 HTML。

做不到其中一条，方案就还没做完。

## 交付

非根 base 双构建保留。第一次根路径 `docs:build` 的未 merge 产物持久化为快照内 `.panel-production-candidate`。确认发布时 `prepareProductionDist` 先检查该候选：

- 有效：复制到 `.panel-production-dist`，只注入生产 `build.json`，不调用第三次 `docs:build`。
- 缺失、损坏、带 `/release-preview/` 前缀、或带预览 `build.json`（`sha: null` / `jobId`）：fail-closed 回退现有根构建。
- 生产准备后恢复 live `docs/.vitepress/dist`，release-preview 仍可用。
- 部署打包目录是 `.panel-production-dist`，不会上传 prefixed/merged 预览产物。

未开始 U-03。未真实发布、push、上传或部署。

## 实现

- `panel/lib/probes.mjs`：非根预览仍先根构建、再预览构建并 `mergeRootSsrIntoPreviewDist`。根构建完成后调用 `persistProductionCandidate`，合并源改为该候选；不再把未 merge 根产物丢在 `.preview-root-dist` 后删除。
- `panel/lib/guonei.mjs`：新增候选目录契约与可用性检查；`prepareProductionDist` 有效则跳过 `build({ previewBase: '/' })`，只写生产 meta。
- `panel/lib/README.md`：补候选产物契约。

## 测试（先红后绿）

公共缝：`probes.build`、`prepareProductionDist`、`probes.deploy`。

红：复用有效候选仍走第三次构建；双构建后不存在 `.panel-production-candidate`。  
绿：`node --test panel/probes.test.mjs panel/guonei.test.mjs` → 27 pass / 0 fail。

覆盖：

- 成功复用：不调用 `build`，生产目录是纯根内容 + `sha`/`builtAt`，候选本身不被写入生产 meta。
- 缺失回退：无候选时调用现有根构建。
- 损坏/前缀回退：空 `index.html`、缺 `index.html`、`/release-preview/` HTML、预览 `build.json` 均回退，不把 leaked preview 送进生产 hold。
- preview dist 恢复：复用与回退、以及构建失败后，live dist 仍是 release-preview。
- production meta：复用与回退都写入指定 SHA/builtAt。
- deploy：有效候选时 `tar` 的 cwd 为 `.panel-production-dist`，内容无 `/release-preview/`。

既有目标页 / 404 壳 / 锚点校验与双构建回归仍通过。

## 原则

- KISS / YAGNI：候选契约收在 `guonei.mjs`，`probes.build` 只负责在合并前持久化。
- DRY：生产 hold、preview hold、meta 写入仍走原函数。
- 单一职责：可用性检查 fail-closed，不开放上传预览产物。

# 方案：发布面板预览与上传性能优化

## 目标

在不削弱发布前预览、Git 推送、国内站原子切换和生产 SHA 校验门禁的前提下，缩短发布面板的等待时间，并让长阶段可观察、可恢复。

成功尺度：

- 「保存并生成发布预览」不再被公众号线上图片检查和条目列表刷新阻塞；正常本地环境下以 VitePress 双构建本身作为主要下限。
- 「确认发布」复用同一快照在预览阶段产生的纯根路径候选产物，候选失效时自动回退重新构建。
- 国内站支持带完整回退的增量上传，保持 `.new → 原子替换 → build.json SHA` 语义。
- 面板能展示 `Committing / Pushed / Deploying / VerifyingProduction` 等真实阶段，不把单个长 HTTP 请求表现成无反馈卡死。
- `pnpm test:panel`、`pnpm docs:build` 通过；新增测试能证明优化路径和回退路径。

## 已确认事实

- 非根 base 发布预览当前串行运行两次 `pnpm docs:build`，历史 PreviewReady 中位数约 14.4 秒。
- 确认发布还会再次执行根路径生产构建，然后全量 tar、SCP、SSH 原子切换并轮询生产 SHA。
- 最近生产产物约 54.69 MiB；相邻两份产物中新增或变化约 11.32 MiB，具备显著增量传输空间。
- Windows 非根 base 曾生成 `NotFound` SSR 壳；双构建和根 SSR 合并是现行 fail-closed 修复，不能未经复现和替代验证直接删除。
- 当前 `GET /api/publish/jobs/:id` 是只读查询；推进核对由 `POST .../continue-verify` 完成。

## 约束

- 不改变发布范围、确认令牌、manifest 哈希漂移检查、`main` 分支门禁和生产 SHA 验证。
- 不在用户确认发布前执行任何远程上传或部署。
- 不 push、不发布、不部署；只做本地代码、测试、分支 commit 与获批范围内的本地集成。
- 不删除现有快照，不把快照保留策略纳入本轮；只记录后续事项。
- 不新增运行时依赖，不假设 Windows 有 rsync。
- 不修改 public blog 内容、`.env`、凭据、`AGENTS.md` 或 `.agents/memory/`。
- 当前用户主检出很脏；不得在该检出集成，不得带入无关改动。

## 非目标

- 本轮不尝试删除或并行化发布预览双构建。
- 不优化博客图片、字体体积。
- 不修改 Cloudflare Pages 发布方式。
- 不做生产机探测性上传或真实性能压测。
- 不自动清理 5 GiB 既有快照。

## 建议交付范围

1. 非阻塞预览与发布进度可观察。
2. 生产候选产物复用及失效回退。
3. 国内站增量部署及全量回退。
4. 串行集成、测试和只读本地性能对比。

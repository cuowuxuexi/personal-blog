## 方案覆盖

### U-01 / 非阻塞预览与真实阶段反馈

ACCEPTED

- `PreviewReady` 不再等待线上公众号图片 probe；probe 仅控制公众号复制门禁。
- 后台结果只补丁当前 job 的 wechat 字段，不覆盖发布状态。
- confirm 飞行中前端以只读 GET 轮询，展示 `Committing → Pushed → Deploying → VerifyingProduction`；不误发 `continue-verify`。
- draft 后 bootstrap 失败不再阻断 prepare。
- 发布 token、manifest、baseSha 与确认前不得上传的边界未改变。

### U-02 / 复用预览根产物作为生产候选

ACCEPTED

- release preview 仍保留 Windows 非根 base 兼容双构建和 fail-closed 校验。
- 只持久化未经过 SSR merge 的纯根 dist 到 job 快照 `.panel-production-candidate`。
- 候选与 job 快照、base、manifest/build 配置匹配时跳过第三次 `docs:build`，只写生产 `build.json`。
- 候选缺失、损坏、带 release-preview 前缀或元数据不一致时回退现有根构建。
- 生产准备后 release preview dist 仍保留。

### U-03 / 国内站增量部署与全量回退

ACCEPTED

- SHA-256 manifest 覆盖可上传文件；路径、删除清单和 shell 数据均 fail-closed。
- delta 只在远端 manifest SHA、远端 `build.json.sha`、`job.baseSha` 三者都存在且相等时启用。
- added/changed 进入 delta，deleted 在 `.new` 内删除，unchanged 不传输；最终仍走 `.new → 原子目录替换`。
- full/delta 共用部署锁；delta 持锁后复核 manifest 原文摘要，关闭基线 TOCTOU。
- 每任务使用随机唯一远端 tar，关闭锁外 SCP 覆盖；成功和失败均尽力清理自己的远端归档。
- 缺/坏清单、基线不匹配或 delta apply 失败时回退全量；锁竞争则安全失败，不覆盖并发任务。
- 不新增运行时依赖，不要求 Windows/生产机安装 rsync。
